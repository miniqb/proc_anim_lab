项目最近的“渲染美化”，不是给球体贴一层更复杂的材质，而是把运动内核的观测结果重新解释成连续的身体、腿、甲片、羽毛与生命感。物理仍然负责“它在哪里”，渲染负责“它看起来像什么”。

01 / 09
The idea

先把“美化”翻译成一条数据管线

内核的 chunk、连接和足端是为了算运动；它们是可靠的骨架数据，却不是最终应该出现在屏幕上的形状。正式渲染器从这些数据读取位置和状态，经过一层只读的视觉解释，再生成网格。

01

只读观测

读取 LerpPos(alpha)、半径、支撑法线、足端状态。渲染不会反过来改腿或身体。

02

样条密化

几个 chunk 只是控制点。Catmull–Rom 在它们之间补出连续、可过采样的曲线。

03

扫掠成管

沿曲线每一步生成一个截面环，环与环之间拼成三角形，球链就变成了身体。

04

解析剖面

显示半径、颜色和呼吸来自弧长函数，不必等于物理半径，也不必随 chunk 阶梯变化。

05

剪影优先

Unshaded 平色与少量烘焙明暗保持大块轮廓；重叠的内部接缝因此消失。

02 / 09
Typical creature / Lizard

一只蜥蜴，在一帧里到底经历了什么？

蜥蜴最适合当例子：它同时包含连续身体、尾巴、腿、背刺、头部和颜色渐变。下面的六步，基本也是其他“链状怪物”的共同骨架。

STEP 01 / INTERPOLATION

先画一个“刚刚发生”的位置

内核每个 tick 保存 LastPos 与 Pos。渲染帧不直接拿当前点，而是用 alpha 在两者之间插值：这样 40Hz 的逻辑运动仍能在更高的画面帧率下连续显示。

drawPos = Lerp(lastPos, currentPos, alpha)
alpha 来自物理 tick 余数；它属于画面，不进入运动哈希。
STEP 02 / CONTROL POINTS

物理球是“磁铁”，不是外壳

蜥蜴的控制点按顺序收集：头前伸点 → 脊柱 chunk → 尾链 chunk → 向外推开的尾尖。头前伸与虚拟尾尖让曲线超出球心，端部才能自然收锥，不会像一串穿过中心的珠子。

points = [head + neckDir × headR × .8, spine…, tail…, tailTip + tipDir × .09]
控制点决定姿势；显示半径和颜色另算。
STEP 03 / SPLINE

控制点之间，补出“身体应该经过的线”

SplineSampler 使用 Catmull–Rom：内部点用中心差分得到切线，端点用单边切线。每一小段再采样四次，最终的站点比物理 chunk 密得多。半径和颜色也用 smoothstep 过渡，避免在控制点处出现折痕。

station(t) = cubic position(t)
profile(t) = Lerp(a, b, 3t² − 2t³)
STEP 04 / SWEEP

每一个站点都长出一圈截面

对每个曲线站点，先得到切线 tangent，再把上一个截面的 up 投影到新切线的垂直平面。这叫平行传输 frame，比每段独立计算法线更不容易突然扭转。最后用 10 边环与下一环拼成三角形。

vertex(θ) = center + radius × (side·cosθ + up·sinθ)
ring → ring → ring；两端加锥形端帽。
STEP 05 / RENDER IK

物理只找脚，画面负责补膝

运动内核的腿是足端粒子：它寻找真实地形落点、支撑和迈步。正式渲染器读取 root 与 foot，再用两骨 IK 解出 knee，之后把 root → knee → foot 也扫成一条细管。膝盖不会碰撞，也不会给身体施力。

cos = clamp((d² + L₁² − L₂²) / (2dL₁), .2, .98)
钳制的意义：腿不完全绷直，也不完全对折。
STEP 06 / COSMETICS

把“像活的”放在渲染侧

低速时前胸随正弦相位呼吸，尾梢逐渐染上品种色，背刺挂在管道的背侧，头部颜色慢慢脉冲。它们都是化妆状态：不改内核、不进确定性哈希，却让同一套运动看起来不像工程图。

breath ∝ sin(time) × pow(1 − runSpeed, 2)
跑起来呼吸减弱；停下来，轮廓重新有微小起伏。
图中亮点是物理控制点，暗色管带是渲染结果。注意：管带并没有逐球贴着物理半径走，而是对身体做了修长的显示剖面。
03 / 09
Geometry / The anti-ball recipe

让球链消失，靠的不是更高模，而是三次“换译”

身体仍然是 chunk 链，但屏幕上看到的东西已经不是 chunk 链。每一步都在削弱离散物理结构的视觉证据。

translation 01

物理半径 ≠ 显示半径

物理半径要服务碰撞和约束；若照画，重叠球会显得臃肿。蜥蜴身体显示半径大约取物理半径的 0.85，髋部进一步收至 0.72；尾巴则按尾部视觉需要放大。身体因此读成一条有厚薄变化的躯干。

translation 02

离散点 → 密集站点

chunk 之间不是一条直线，而是一段带切线的 cubic 曲线。每节采样 3～4 次，颜色和半径使用 smoothstep。点越密，后续的管环越小，弯曲就越像连续组织而不是折线。

translation 03

线段 → 管状表面

每个站点生成一个 7～10 边截面环；相邻环拼 2 个三角形。首尾加端帽，端点向外推一小段并收细。视觉上，身体成为一根可以弯曲、变细、染色的管。

一个截面环

side 和 up 组成截面平面，tangent 是曲线前进方向。将这个环沿曲线重复，就得到身体表面。

为什么不会一路拧麻花？

代码没有让每一段自己“猜”一个 up，而是把旧 up 最小旋转地带到新切线。这样 support normal、背脊刺、疣珠和管截面共享稳定的朝向。

关键的视觉欺骗：身体管和物理球可以相互穿插。只要外层剪影连续，且重叠的图元使用同一张平色材质，内部接缝就没有足够的颜色/光照证据暴露出来。
04 / 09
Legs / Derived pose

脚是真实的，膝盖是“画出来的”

这是运动与渲染分层最容易被误解的地方：正式外观有完整的腿，但内核不需要真的模拟每一段大腿和小腿。

两骨 IK 做了三件事

  • 把脚连接到身体：root 来自腿的锚点，foot 来自内核足端的插值位置。
  • 选择弯曲侧：pole 由身体轴、支撑法线和腿的左右侧共同决定，并且低通，避免膝盖每帧翻面。
  • 限制不自然姿态：余弦定理的结果被钳在 [0.2, 0.98]。所以视觉上的腿永远保留一点弯曲，不会像一根拉直的尺子，也不会折成反向关节。
重要：knee 只存在于 renderer。它不参与碰撞、不承重、不反推足端；正式渲染可以很漂亮，运动内核仍保持“一个足端粒子”的简单与确定。
05 / 09
Palette / Silhouette

颜色不是“涂满模型”，而是给剪影分配稀缺信号

雨世界式的识别感来自大面积单色剪影，颜色只在眼睛、头、足端、尾尖、羽梢或甲片上出现。颜色分区同时也是几何融合策略。

silhouette black
effect color
support accent
breed signal

整只生物不是一套 PBR 材质。 管件使用 Godot StandardMaterial3D 的 Unshaded 模式与顶点色作为 albedo；颜色沿管站插值，内部的球、管、鳍片、腿在需要融合的地方共享同一近黑色。这样圆片盖住条带、腿插入身体、球团彼此穿透时，接缝不会因为实时光照而变成一圈亮边。

当前 TubeMeshBuilder 仍可在 CPU 端把约 22% 的包裹漫反射烘进顶点色：它不是实时阴影，只是让截面有一点体积读数；把 ShadeAmount 设为 0，就会回到纯平色。

sRGB 的小陷阱：在带 tonemap 的场景里，顶点色若按 linear 方式解释，原本的剪影黑会被抬亮，球和管就会变成两种灰褐色，根部融合失效。Daddy 的正式渲染器显式使用 VertexColorIsSrgb = true，保证管根顶点色和球体 AlbedoColor 在同一颜色空间；其他已经按旧观感调好的验证件暂时保留自己的调色。
06 / 09
Four visual grammars

大多数怪物共享管线，但身体不只有一种画法

共享的是“读状态 → 组织曲线 → 生成几何 → 上色”的思想。不同物种在“身体如何占据空间”这一步，选择了四种策略。

蜥蜴：一条连续的身尾管

最典型的“去球感”案例。头前伸、脊柱和尾链进入同一组控制点，最后用一个扫管器连续覆盖身体与尾巴。物理 chunk 的球形只保留为运动骨架，背刺、头、眼和足端色是附加的识别层。

几何
Catmull–Rom + 10 边截面环
剖面
身躯收窄、尾梢收锥、低速呼吸
颜色
近黑身体 + 品种色头/尾/足端

蜈蚣：暗底管 + 背甲节片

先用一根近黑的连续底管把节间连起来，再把每个 chunk 变成略短、略扁的椭球甲片。甲片之间露出的暗底管自然形成节间暗环，不需要另外画缝。每节的真实 SupportNormal 经低通后负责 3D 定向，替代 2D 里的假 roll。

几何
全链扫管 + 每节独立背甲
识别
亮甲片 / 暗节间 / 外拱腿
附肢
两端触须使用渲染侧摆相位

秃鹫：用一个替换件盖住刚架

秃鹫的四个躯干 chunk 形成 K4 风筝刚架，但屏幕上不把四个球画出来，而是用一个带完整正交基的椭球躯干覆盖它们。脖子和翅臂仍然扫管，羽毛则是沿翅链分布的刀片扇。

长腿爸爸：同色球团的联集错觉

它不强行把身体焊成一张 SDF。多个球体共享同一张近黑 unshaded 材质，并将显示半径放大到 1.1r + 0.05m，球间的内部棱线就会被同色和互穿隐藏。触手从球心起笔，根部保持纯黑，之后才极克制地渐染。

07 / 09
Cosmetic state

生命感来自“系统开关”，不是一段死亡动画

真正有趣的地方，是许多小动作都不需要新的动画资产。它们只是渲染侧状态在不同条件下打开或关闭。

BREATH

停下才会呼吸

呼吸幅度乘上 pow(1 − runSpeed, 2)。跑得越快，身体越像一个稳定的运动器官；停下后，前胸才出现细小的慢起伏。

SEED

出生时决定个体差异

装饰普查使用稳定 seed：眼睛相位、疣珠位置、垂索数量、羽毛磨损都在出生时冻结。相同 seed 重跑，视觉个体仍然相同。

LAG

附肢不要瞬间同步

秃鹫羽毛方向与长度使用低通追目标；蜈蚣的 up 沿链平滑；Daddy 的垂索用 Verlet。轻微滞后比“每帧精准贴合”更像有重量。

DEATH

死亡是关闭伺服

关闭腿的主动追点、头部伺服和呼吸，保留重力、阻尼和距离约束，身体自然垂下。姿态的坍塌来自系统少做一点事。

08 / 09
Boundary / Performance

渲染层很自由，但有三条不能越过的线

这些约束确保“变漂亮”不会悄悄改变运动行为，也让正式渲染可以被安全地移植回主项目。

层负责什么不负责什么
ProcAnim.Corechunk 位置、连接、足端、支撑法线、物种运动状态不认识 mesh、材质、颜色和膝盖
FormalRenderer读取插值位置，组织控制点，生成身体/腿/装饰不写回内核、不参与碰撞、不进物理哈希
Cosmetic state呼吸相位、稳定 up、bend pole、羽毛滞后、垂索不成为 AI 或运动的隐藏输入
Material / Palette近黑剪影、品种色、顶点色、轻微烘焙明暗不依靠复杂实时光照来修补几何接缝
line 01

V 键是对照实验

沙盒同时保留 debug 白盒：每个 chunk 一个球，连接和腿是线。切到正式模式，才能看见哪些视觉层是“解释”而不是“新的物理”。

line 02

CPU 重建是有意的

当前验证实现以 ImmediateMesh 每帧清面并重发三角形；单只生物几百个顶点，优先换取可读、可调、可验证。不是 shader 蒙皮，也不是 metaball 管线。

line 03

不为“消球”重做碰撞

物理仍用原来的球和真实地形查询。渲染管只是视觉表面，不能拿它替代碰撞网格；这一点正是运动与美术解耦的价值。
