# 已知问题：三节脊柱转向时中段领先头段

> 状态：**暂缓修复，保留回归指标**  
> 记录日期：2026-07-22  
> 影响品种：`heavy`、`hexapod`（`SpineSegments = 3`）

## 1. 现象

生物已经在地面行进时，如果宿主突然把 `MoveTarget`（胡萝卜）切到侧面，三节脊柱通常会先由
中段转向，头段随后跟上。最终头部仍会朝向目标，身体也会重新展开，不会稳定滞留成 Y/V 形；
问题是中段领先的幅度和持续时间肉眼可见，`hexapod` 尤其明显。

这不是此前的“爬墙时髋部长期卡住/脊柱持续折叠”问题：当前场景在纯平地复现，且所有事件都能
自行恢复。

## 2. 固化复现

交互模式：选择 `heavy` 或 `hexapod`，让其稳定行进，再用 Shift + 右键把胡萝卜切到侧面。

确定性场景：`--route=carrot-turn` 会在纯平地稳定行进中，将 External 胡萝卜交替向左右侧转
约 90°；切换发生在旧目标尚有余量、头部仍有明确前进速度时，不是到点停住后重新起步，也不触发
只服务近 180° 掉头的 `TurnAssist`。

## 3. 当前基线（40 tick/s）

| 指标 | heavy | hexapod |
|------|------:|---------:|
| 完整恢复事件 | 54 / 54 | 47 / 47 |
| 中段先过 60° 对齐阈值 | 51 / 54 | 45 / 47 |
| 中段相对头段的最大转向进度领先 | 51.9° | 64.1° |
| 领先超过 5° 的最长连续窗口 | 13 tick（0.325s） | 16 tick（0.40s） |
| 头段晚过同一阈值的最大时间差 | 7 tick（0.175s） | 9 tick（0.225s） |
| 中段相对头部沿新方向的最大平移领先 | 0.060m | 0.077m |
| 头前构型恢复最大耗时 | 12 tick | 20 tick |

指标里的两根局部轴定义为：

- 头段：`Head - SpineFollower`；
- 中段：`SpineFollower - Hips`。

`maxMiddleLead` 比较两根局部轴相对事件起点的转向进度，不拿 `Head - Hips` 整体长弦代替头段；
`maxFrontLagTicks` 比较两根轴越过“与新方向夹角 ≤60°”阈值的时间。整体长弦只参与最终恢复判定。

## 4. 已确认机制与尚未证实的假设

已确认：

1. `MoveTarget` 的方向仍由 `Head` 计算，导航控制权没有交给中段。
2. 同一 tick 内，`Head` 追目标，`SpineFollower` 主动追「头后（背离目标侧）半节长」的拖尾点
   （2026-07 wall-pose 失稳修复后语义；修复前拖尾点在目标身后一节、恒在头前 ~0.2m）；
   `Hips` 被动拖行。
3. 中段是两条刚性连接之间的活动铰点，局部轴也比整体/前段基线更敏感，因此允许短暂领先。
4. `hexapod` 的中间腿对会读取中段局部轴，放大视觉效果；腿不向身体回传反力。`heavy` 同样复现，
   所以问题不由第三对腿单独造成。

最值得优先验证、但**尚不能视为唯一根因**的假设是：胡萝卜距离过远会显著放大领先。

当前定向场景把目标放在头部约 4m 外，而 RW 式 `MoveTarget` 原本更接近“下一个邻近路径格”。在理想
90° 转向、脊柱节长 0.3m 时：4m 远点会让头部与中段的施力方向只差约 4.6°，几乎同步转向；若局部
胡萝卜距离约 0.5m，中段拖尾方向会保留更多旧身体方向，理论上更容易形成头部先转。尚未执行
`0.5m / 1m / 2m / 4m` 同场景距离扫描，因此不能断言“只要限制距离，问题就一定完全消失”。

## 5. 当前回归边界

`carrot-turn-heavy` 与 `carrot-turn-hexapod` 已进入完整矩阵。当前硬断言保证：

- 800 tick 内至少发生 35 次有效行进中切向，左右两种手性各至少 12 次；
- 切向前实际仍在移动，旧目标剩余距离至少 0.8m；
- LizardLocomotionController 实际收到的旧/新胡萝卜方向约为 90°；
- 恢复窗口始终为 External，且没有误触 `TurnAssist`；
- 头—中段前向构型、整体轴、脊柱展开与沿新方向移动在 25 tick 内稳定恢复。

中段领先角度、领先连续 tick 和头段阈值延迟目前是**诊断指标，不是审美硬门**。这是有意设计：
先保存现状证据，未来决定目标手感后再设阈值，避免把 RW 式合法软体相位差直接判错。确定性哈希仍会
发现轨迹的任何无意漂移。

## 6. 暂缓决定与未来处理顺序

2026-07-22 决定：本轮不修改 LizardLocomotionController/身体物理，仅保留复现、指标和矩阵覆盖。

以后重开时按以下顺序处理：

1. 用完全相同的事件条件跑 `0.5m / 1m / 2m / 4m` 距离扫描，先确认距离与领先量的因果关系。
2. 若约 0.5m 已足够：把鼠标点击/AI 给出的远点视为最终目的地，由宿主持续喂邻近可达的局部胡萝卜
   （真实关卡应喂下一个导航路径点），不改核心施力。
3. 若多个宿主都可能误喂远点，可考虑在核心内部只钳制“推进伺服距离”，到达判定仍使用原始最终目标；
   这会扩大 `MoveTarget` 契约，须重新审核墙面重定向与调试绘制语义。
4. 若局部胡萝卜后仍明显领先，再增加温和、几何驱动的头部优先：急转时只把中段推进衰减到约
   50%–70%，对齐后恢复；不得降为零，以免重新引入三节脊柱无中段驱动力的 V 形折叠。
5. 不优先改 BodyStiffness、质量或约束权重；这些会同时影响行走、爬墙、翻越和墙角恢复。视觉层提前
   转头只能作为最后润色，不能替代物理修正。

可供下一轮讨论的候选目标（尚未启用）：头段阈值延迟 ≤3 tick、领先超过 5° 的窗口 ≤6–8 tick、
最大转向进度领先约 ≤30°–35°，同时保持 25 tick 恢复门和完整矩阵全绿。
